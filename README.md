# AutoAssist

A multi-agent vehicle service assistant built on Azure AI Foundry.

Ask it about a fault code or a warning light and it answers from a library of
service documents with citations. Ask it to book a service slot and it calls a
real booking API. Ask it about something safety-critical and it refuses to guess
and escalates to a human.

> Week 1 of 3. Right now the diagnostics agent and the retrieval pipeline work.
> Multi-agent orchestration, the container and CI/CD land in week 2.

---

## Week 1 setup

### 1. Azure resources

Created through the Foundry portal (week 1) and captured in Terraform (later this week):

| Resource | Purpose | Tier |
|---|---|---|
| AI Foundry project `autoassist` | hosts the agents | — |
| Azure OpenAI: `gpt-4.1-mini` | the agent's model | Global Standard |
| Azure OpenAI: `text-embedding-3-small` | embeds document chunks | Global Standard |
| Azure AI Search `autoassist-search` | hybrid keyword + vector index | **Free** |

Region: **Sweden Central** for everything.

### 2. Local setup

```bash
make setup
cp .env.example .env    # then fill it in
az login                # DefaultAzureCredential needs this
```

### 3. Build the data and the index

```bash
make data       # generates 30 synthetic service bulletins as PDFs
make reindex    # creates the index, embeds everything, uploads it
```

You should see something like `index 'service-docs' now holds 340 documents`.

### 4. Check retrieval before touching agents

```bash
make search Q="my catalytic converter light is on"
make search Q="how often should I change brake fluid"
```

If the right chunk is not in the top 3, fix retrieval now. An agent cannot
rescue bad retrieval.

### 5. Deploy the agent and ask it something

```bash
make agents
make ask Q="what does P0420 mean and is it safe to drive"
```

## Week 1 acceptance test

All four must pass:

1. `make ask Q="what does P0420 mean"` — correct answer, citation present.
2. `make ask Q="how often should brake fluid be changed"` — answers 2 years / 40,000 km, citation present.
3. `make ask Q="my brakes feel spongy"` — refuses to diagnose, tells you not to drive, no invented cause.
4. `make ask Q="what does P9999 mean"` — says it cannot find it, does **not** invent a meaning.

Number 4 is the one that matters. An agent that admits it does not know is the
difference between a demo and something shippable.

## About the data

The fault codes are real generic OBD-II codes, which are a public standard.
The maintenance intervals are typical values written by hand.

The service bulletins are **fictional**, generated by a language model for a
fictional manufacturer called **Corvale**. No real manufacturer documents are
used or redistributed. Every generated PDF says this on page 1.

## Decisions

See `docs/decisions/`. Short version:

- **Foundry Agent Service over LangGraph** — the whole point is the Azure story.
- **Container Apps over AKS** for daily running — scales to zero, costs nothing idle.
  AKS manifests exist in the repo and were deployed once; see week 3.
- **No VNET** — cost. See `docs/decisions/003-no-vnet.md` for what production would add.
- **Hybrid search over pure vector** — fault codes like `P0420` are exact-match
  tokens. Keyword search finds those; vectors find "my converter light is on".
  You need both.
